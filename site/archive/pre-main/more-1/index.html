旧版运行手册 · 续 1

这不是模型概率，也不用于过滤或替换 benchmark 中模型选择的动作。演示脚本仍输出默认 128 步的短片。 对比固定环 v1 与动态修复 v2 的相同种子（不渲染、不等待网页），保存通关率、步数和决策耗时：

在标准 10×10 棋盘、种子 0–999 的同种子对照中，两版都 1000/1000 通关； 平均步数从 2288.563 降为 1621.273（减少 29.16%），这组种子中每一局都减少了步数。 本机四进程验证时平均规则决策耗时从约 0.016 ms 增为 0.293 ms；不包含棋盘渲染和网页闭环等待。 这些是上述固定种子集的实测结果，动态修复不保证全局最少步数。

新事件增加 observation、episode_end，step 增加 observation_state、question、choices； evaluation_state 继续表示执行后的状态。读分协议仍为 v4。

本地服务接口：GET /api/events?cursor=0 返回增量卡片帧、下一 cursor 和控制状态； GET /api/card.png?id=<帧号> 返回 Python 决策快照卡片； GET /api/export.gif?episode=<局ID>&timing=realtime 导出真实时间版，timing=backend 导出去页面等待版； 可用 recording=<录制ID> 指定同一片段； POST /api/recording 接收带时间戳的浏览器 PNG 批次，按录制 ID 和偏移量幂等保存。 交互模式接受 POST /api/control（JSON）： {"command":"new","mode":"rules","seed":0,"max_steps":128,"method":"choice","condition":"no_plan"} 创建局， pause / resume / step 控制规则运行，{"command":"action","action":"left"} 提交人工动作。 {"command":"rendered","session":"<局ID>","step":1} 确认显示完成，并记录该步闭环耗时； 规则模式还以此放行下一步。控制请求可携带 cursor，响应中的 events 返回该位置开始的增量事件； 控制响应还包含 loop_timings 和单调递增的 revision；人工动作可携带 session 与执行前 step， 后端拒绝旧局／过时步骤的动作，避免延迟请求重复推进或误入新局。 只读 --run 模式拒绝控制请求。

输出与代码结构

Section titled “输出与代码结构”
查看本节历史配置与命令

每次运行生成 run.json（配置、实验清单、模型 / 模板指纹与代码哈希）、events.jsonl （即时刷新）、summary.json、metrics.csv、run.log，可选每局 GIF。 失败后保留证据并继续独立实验；指标只使用成功结果，显式列出失败、不支持和待完成数量。 进程意外终止后可以从事件离线汇总，尾部未写完整的事件不会计入成功结果。 Python 入口的 run.log 记录运行错误；批量 smoke 额外保存子进程完整 stdout / stderr。

core 不导入具体 bench，models 只处理模型格式，backend 只处理推理请求。 每个 bench 自己定义任务规则、规划提示词、实验清单与指标。模型适配器报告 supports_thinking，由 bench 映射到自身支持的实验条件。 导入公共 API、生成实验清单、离线汇总均不加载 torch / Transformers / vLLM 推理运行时。

原有 from vdecision import Engine, Sampling, SnakeBench, BenchResult 保持可用；内部模块 路径已按上表迁移，例如 vdecision.engine → vdecision.core.engine， vdecision.transformers_backend → vdecision.backends.transformers。run.py 仍是兼容入口。 Snake 的协议、提示词、实验数量保持不变；新 run.json 增加 bench 标识， BenchResult.load() 自动选择对应汇总器，并兼容没有该字段的 Snake v1 / v2 结果。 源码哈希和 --freeze-only 均递归包含整个包，保留相对路径。

新增任务可通过 engine.plan(..., instructions=PlanningPrompt(...)) 提供 reasoning 请求、 直接规划请求和后续读分上下文；读分上下文保存在 Plan.details 中并随规划复用。 低层 Engine.plan() 不再默认使用 Snake 提示，省略 instructions 时使用通用任务提示。 手动重现 Snake 规划时传 vdecision.benches.snake.prompts.PLANNING_PROMPT； SnakeBench 已经自动传入。

缓存与运行时

Section titled “缓存与运行时”
查看本节历史配置与命令
  • 开发与 GPU 任务统一使用 .venv/bin/python，它指向共享存储上的 .python/bin/python3.12（Python 3.12.11）。依赖包仅保存在 .venv 中， 不重新安装、不升级，也不在每次实验中复制解释器。.python/ 不纳入 Git。
  • .venv 的解释器不能依赖开发容器的 /root/ 路径；GPU 容器需要以相同路径 挂载项目，才能访问解释器、依赖和模型。激活方式为 source .venv/bin/activate。 如将来重建虚拟环境，显式使用 uv venv --python "$PWD/.python/bin/python3.12" .venv； 这不是日常启动步骤，重建后需按锁文件恢复依赖。
  • 原 .runtime 及其仓库外备份已删除。新任务使用 .venv/bin/python， 调度配置与日志放在对应的 outputs/<运行目录>/ 中；提交配置中的凭据不得写入 Git。
  • .cache/<架构>-<环境哈希>/ 按依赖版本、GPU、CUDA runtime、nvcc 版本隔离。 启动脚本统一设置 Triton、vLLM、FlashInfer workspace、Torch 扩展和 Inductor 路径。 FlashInfer 自身在 workspace 下使用 .cache/flashinfer。
  • 上次 H100 的可用缓存已迁移至 .cache/sm90-571889de354e/。 迁移核对 357 个缓存文件、5102 个运行时条目，308 处 Triton 绝对路径引用有效； 原迁移记录随旧运行时备份删除；环境匹配才复用此缓存目录，其他环境单独隔离。
  • 现存 FlashInfer autotune 文件只有元信息，不算有效调优缓存；旧容器中 未持久化的 JIT 文件无法恢复。后续 JIT 使用持久化 workspace。
  • 磁盘编译缓存默认复用；进程内 KV 缓存不能跨任务恢复。vLLM 默认开启 APC， 可用 --disable-prefix-caching 关闭。命中率、延迟及数值差异见 standard 后端实验报告。

2026-10-12 已完成入口迁移：核对解释器 4,054 个文件，依赖版本及依赖清单保持不变； 移除仓库内 .runtime 后，依赖导入、当前与新冻结快照的 dry-run、37 项 CPU 测试均通过。

提交前可只冻结最小代码与依赖清单；相同内容复用同一快照，不复制解释器、依赖和缓存。旧快照保留原样， 不再直接启动其中引用旧 .runtime 的脚本；新任务从当前代码重新冻结：

脚本不含平台提交、重试或占卡逻辑。GPU 资源与时间上限由下次授权的提交任务管理。
