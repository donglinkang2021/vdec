Drawing v1（历史协议）

正文与示例可直接阅读；加载后可查看保存的请求与逐步操作。

VDECISION DRAWING / VISUAL SPATIAL REASONING

“在两个圆之间，补画一个矩形。”一句话需要模型找到位置、选择工具、控制落笔，再判断何时完成。

这里把一次空间绘图拆成可检查的图片、模型请求和环境动作。你可以逐步看见：哪部分是模型输入，哪部分是规则策略给出的示范，以及一次选择何时真的改变画布。

真实模板，不等于真实模型成绩。
本文输入由三类模型的本地 tokenizer／processor 与现有适配器组装；输出示范来自知道参考解的规则策略。没有加载权重，没有执行模型推理，也没有候选分数或生成计划的实测值。
先看三种方法怎样选择 ↓对照 Brush 的二分控制 ↗单文件离线阅读

01 / 看图补绘

已有图形用字母标记。模型只收到自然语言要求和当前画面，题目不提供答案坐标。开发集 36 题、测试集 72 题，六类等量；每题已有 2–5 个对象，新增 1–3 个图形。

Section titled “5 次和 43 次请求，究竟在问什么？”


选择拆解 / 先选操作，再补参数
先把一次决策分成两层：做什么，以及需要什么参数。七种操作始终可选；只有选中 move 时，readout 才继续四轮定位。全部参数选完后，环境才执行一次动作。
操作选择的固定映射；字母是 choice 的候选 token
字母语义操作选中后还缺什么？
Atool · 选择工具工具种类
Bcolor · 选择颜色六种颜色之一
Cmove · 移动落点位置
Ddown · 落笔无
Eup · 抬笔无
Fundo · 撤销无
Gfinish · 提交无
choice：同一请求列出 A–G，读取这七个字母的下一 token 分数，选分数最高的字母，再查表得到操作。输入尾部已预填 \boxed{；它不是模型输出。选到 C，只代表决定移动，仍没有落点。
yes_no：同一张图和状态，分别配七个问题：“选择工具是否最佳？”“选择颜色是否最佳？”“移动是否最佳？”……每个请求同时读 yes 和 no 的分数，算出 yes 在这两个候选中占的比例；比较七个比例，取最高者。不是遇到第一个 yes 就执行，也不是执行七个动作。七题可批量处理，仍计七个模型请求。
coordinate：一次生成一个 JSON，例如 {"action":"move","x":43,"y":42}，同时给出操作和参数。没有 A–G 读出，也没有四轮九宫格追问；由严格解析器检查后交给环境。
分数是怎样计算的？
设 ℓ 是模型返回的候选 token 的 log-prob（对数概率）。下面只有公式，没有实测或虚构的分数。
choice：sᵢ = exp(ℓᵢ) / Σⱼ exp(ℓⱼ)
        在 A–G 的 s 中选最大值 → 映射回语义操作

yes_no：qᵢ = exp(ℓᵢ,yes) / [exp(ℓᵢ,yes) + exp(ℓᵢ,no)]
        sᵢ = qᵢ / Σⱼ qⱼ
        在七个候选的 s 中选最大值 → 语义操作
yes_no 的第二次归一化不改变排序，因此最大 q 与最大 s 对应同一个候选。每题一次就读取 yes 和 no 两个分数，不需要两个请求。七个 q 可以同时很高或同时很低，程序仍取最大值；它们不是任务成功率。决策依据是候选分数，而非只看采样出的一个 token。

    06 / 完成，不只是看起来像
    完整成功要求自主提交、数量与类型／颜色正确、全部关系满足，并且没有额外图形或未完成笔画。对齐和轮廓容差为 8，尺寸比例允许 10% 相对偏差，要求分离时至少间隔 16。
