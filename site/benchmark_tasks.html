Benchmark 说明：main-v1§

协议 snake-bench-v8，套件 main-v1。四套静态图片均为 108 张、dev 36／test 72，benchmark 自动绑定图片，禁止任意任务／数据组合。

默认展示 Perception、Readout、Safety 三个核心榜；Decision、Episode 为补充评测，不合成总分。可通过 离线交互文章 查看截图、真实输入模板与规则回放。

任务与主指标§

榜 每图提问 唯一主指标
Perception 10 题 × 正反 2 种顺序 朝向、食物位置、尾巴位置、坐标格子内容四类等权准确率
Readout 选一个动作 × 全 6 种排列 六次选择同一语义动作的截图比例
Safety 3 个动作的碰撞判断 × 正反 2 种顺序 同一排列下三个判断全对；图内平均后对 3/2/1/0 层等权
Decision 选一个安全动作 × 全 6 种排列 图内平均动作安全率，再对 1/2 层等权
Episode 每步读取新截图，最多 128 步 每个配置的平均食物数

Perception 的食物／尾巴各问横纵位置，格子题问头、普通身体、尾、食物、空格。身体位置取身体中部，长度允许时不再固定问颈部。格子题虽然多，整类仍只占四分之一。

Readout 全部动作立即安全，唯一／两个降低食物曼哈顿距离的动作各占一半。食物接近标签仅用于构造和审计，不作为正确性标准。固定左转一致率 100%，固定字母 A 一致率 0%。

Safety 判断的是下一步碰撞。必死局面指三个动作下一步均碰撞，正确安全集合为空；不是终止画面。全答安全／危险均为 25%。

Decision 两层各 54 张，每层 dev 18／test 36。唯一安全／唯一危险动作的位置在每层与划分内平衡；固定左／直／右与均匀随机均为 50%，环境真值 100%。多个安全动作都接受。

图片集与构造约束§

正式评测仅读取冻结文件。新图片使用固定种子 20261015 / 20261016 / 20261017 构造，保存完整状态、来源、family、划分和状态哈希。Perception／Readout 三档蛇长 3–8、9–18、19–32 各 36 张，每档 dev 12／test 24；每个 split 四朝向等量。Perception 食物与尾巴横纵三种答案每种 dev ≥6／test ≥12。跨榜排除旋转、镜像、平移及换食物形成的同一有序身体几何；新集每个基础几何只取一张。构造状态经环境验证，不声称来自游戏轨迹。

Safety 保留原 108 张、96 个 family、12 对案例：

四层样本量不同，主分数仍对四层等权。12 对案例包括尾巴身份、尾端占用、食物位置各 4 对；同一 pair 属于同一 family、split 与规划 seed，不能当作两个独立 family。旧 UI 的尾巴身份配对截图相同但安全答案不同，新 UI 的连接与尖尾使差异可见。尾格在不进食时腾空，所以允许进入。

冻结文件为 safety_v1.json，SHA-256：d9ee6970565e2aa329578f907ab2623f6b40d38b004aabeff743dea7193f6893。新增其他榜的图片时保持此文件不变。

扩展生成条件、独立重复、三模型矩阵和当前问题 CoT 见 实验运行说明。下文四种共享规划条件的计数仍适用；per-step CoT 额外产生逐请求生成开销。

运行与分母§

PYTHONPATH=src .venv/bin/python run.py --benchmark perception --split dev --dry-run

默认 test、no_plan、choice yes_no。dev 下，一个 condition、两个 methods 的评分调用数分别为 Perception 1440，Readout／Safety／Decision 各 432；test 翻倍。yes_no 每次评分有 K 个候选请求，choice 只有一个。请求、评分调用、截图和 family 是不同统计单位。规划生成开销另计，Episode 成本随轨迹变化。

统一 --conditions 选择 no_plan、shared_full、shared_plan_only、shared_no_think。计划按 task 与 seed 生成；同任务的 full/plan-only 共享一份，shared_no_think 单独生成不含思考的计划。规划只看独立外观示例，不看测试截图。每个 family 只属于一个 split 和规划 seed。

leaderboard.csv 每个方法／条件只列一个主分数，配置未完成或只有分片时不排名；合并原始事件后重新计算。diagnostics.json 保留分层、视觉类型、危险召回、误报、死局识别、动作偏好与成本。不同数据版本、split、render 与提示词版本应分开比较。

验证与复现§

datasets_audit.py 检查覆盖、去重、答案、一步真值与 Safety 原始哈希。build_benchmark_explainer.py 从真实 manifest 和主榜汇总函数生成计数及基线，完整请求经三个本地生产适配器导出并验证去重片段重组。

# 数据审计、离线文章构建（只加载 tokenizer/processor，不加载模型权重）
PYTHONPATH=src .venv/bin/python -m vdecision.benches.snake.datasets_audit
PYTHONPATH=src HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python scripts/build_benchmark_explainer.py
# CPU 回归与浏览器验证
PYTHONPATH=src:.:tests .venv/bin/python -m unittest discover -s tests
node tests/test_benchmark_explainer_browser.cjs
node tests/test_benchmark_explainer_http.cjs

CPU 回归覆盖榜单汇总、缺失配置、分片合并、历史协议及文章数据。浏览器验证覆盖断网 file:// 交互、窄屏与键盘操作，以及限速 HTTP 下的提前显示和加载后交互。浏览器安装与文章维护见 源码说明。冻结新集的生成器为 scripts/build_main_datasets.py。

验证结果、环境真值、教学分数和规则回放都不代表已完成新集模型实测。

旧内容见 归档，仅用于历史读取与审计；旧 suite 和 stage 不能从现役入口重新运行。BenchResult.load 与 --summarize 按协议读取历史结果，保持原有指标含义，原始 outputs/ 不修改。
