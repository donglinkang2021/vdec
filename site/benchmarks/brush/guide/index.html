Brush 任务讲解

本文保留已保存的研究结果。交互查看器按需加载，模型记录与规则示范分别标注。

点击后加载已保存的请求与实验记录。不会发起模型推理。

01 / 任务

从“往哪转”到“现在该做什么”

Section titled “从“往哪转”到“现在该做什么””

在 Snake 中，模型主要判断相对方向、碰撞与动作。在 Brush 中，它还要管理工具状态：同一个 pick，在开始时抬笔，在绘制时结束整次尝试。选中 move 后，才进入下一层方向判断。

目标是从绿色 S 到粉色 E 画一条直线。深色准星的中心是笔尖，黄色笔杆只是外观标记。画布包含 33 × 33 个离散位置。

**先区分两个问题：**找到起终点，是定位问题；移动中留下什么形状，是绘制协议的问题。二分定位正确，也可能画出折线。02 / 状态

三个动作，随状态改变含义

Section titled “三个动作，随状态改变含义”

画笔一开始已显示在画布上。这里的 pick 是“抬起笔尖”，不包含从工具栏抓取画笔的额外步骤。三个选项一直可选，错误动作也会消耗一步。

真实环境中的动作语义

当前状态pickmovedrop
idle · 尚未开始抬笔 → lifted无效，消耗一步无效，消耗一步
lifted · 笔尖抬起无效，消耗一步移动，不留笔迹在当前位置落笔 → drawing
drawing · 正在绘制提交 → finished更新笔迹无效，消耗一步

抬笔时的目标是 S，落笔后目标改为 E。drop 会重置两个搜索区间与锁定状态。提前落笔不会被吸附到 S；提前 pick 也会照常提交，由评分器判断是否成功。

03 / 定位

回答“左”，到底会移动到哪里？

Section titled “回答“左”，到底会移动到哪里？”

控制器不直接读取目标坐标。它保存一个“还可能在哪里”的区间；根据答案排除当前笔尖与另一侧，再移动到剩余区间的整数中点。

例如，笔尖在 16，初始区间是 [0, 32]。回答“左”后保留 [0, 15]，下一位置是 ⌊(0 + 15) / 2⌋ = 7。继续回答左、右、同列，就能依次到达 3、5，并锁定该轴。

把一个方向判断变成一次移动

Section titled “把一个方向判断变成一次移动”

教学实验 · 坐标辅助可见

默认例子：16 → 7 → 3 → 5 → 锁定。对应回答：左、左、右、同列。

[0,32] → [0,15] → [0,6] → [4,6] → 在 5 锁定。

目标笔尖剩余候选区间

“同列”是一次回答，不是环境的确认。即使答错，也立即锁定。改变初始位置或目标会重置实验；从历史步骤继续回答会创建新的分支。

查看精确的区间更新公式

每轴保存闭区间 [lo, hi]，初始 [0, 32]，当前位置为 p。

  • 左／上：hi ← min(hi, p − 1)。
  • 右／下：lo ← max(lo, p + 1)。
  • 若区间非空：p ← ⌊(lo + hi) / 2⌋；若为空，以搜索耗尽结束。
  • 同列／同行：保持 p，锁定该轴，直到 drop 重置。

每一步都延续上一步的区间，不重新从画布边界开始。排除当前已被否定的位置，能避免整数中点反复停在原处。

04 / 实践

现在，由你来控制画笔

Section titled “现在，由你来控制画笔”

先选 pick，再通过 move 接近 S。在 S 上 drop，接着找到 E，最后 pick 提交。你可以自己回答方向，也可以逐步查看知道真实位置的规则策略。

**试着犯一个错误：**尚未到达 S 就 drop，或把不对齐的轴回答成“同列”。控制器会执行你的答案，不会用真实位置纠正。默认动作预算是 40 步。05 / 笔迹

每次都判断正确，为什么还会画歪？

Section titled “每次都判断正确，为什么还会画歪？”

横纵轴的中点不一定在目标直线上，二分搜索还可能越过终点。直线工具会替换旧预览，只保留锚点到当前笔尖的一条线；真实画笔会把经过的每一段都留下来。

同一串动作，两种绘制协议

Section titled “同一串动作，两种绘制协议”

Python 规则轨迹 · 非模型输出直线工具：正确起终点之间的一条线。真实笔迹：相同移动留下折线。

直线工具 · 旧预览被替换

Section titled “直线工具 · 旧预览被替换”

真实笔迹 · 每段移动都保留

Section titled “真实笔迹 · 每段移动都保留”

两侧来自同一案例，执行相同动作和方向回答。没有自动拉直真实笔迹，也没有自动吸附正确端点。

因此，默认主评测采用直线工具，主要测试视觉定位与动作状态控制。真实笔迹模式用于检查移动协议的限制。要测连续描线能力，应另设小步移动等动作协议。

06 / 评分与证据

怎样才算完成这条线？

Section titled “怎样才算完成这条线？”

一局成功需要：已经提交、落笔点恰好是 S、结束点恰好是 E，且全部笔迹到目标线段的最大距离不超过 0.25 个格距。端点必须精确对齐；容差仅用于笔迹偏离。路径长度比单独报告，不加入成功判定。

题集包含水平、垂直、对角线、缓斜率、陡斜率和边界六类。每类开发集 6 题、测试集 12 题，共 36 / 72 题。主指标先算每类的完整成功率，再对六类等权平均。

模型实际上看到什么？

动作请求：任务说明 → 当前文本状态 → 当前图片 → pick / move / drop 选项。状态只含 phase、目标名称 S/E、回答产生的锁定状态与剩余步数；不含坐标、真实对齐标签、区间或正确答案。

这是输入结构示意，不是某个模型的原生模板。两个追问分支带有同一状态、同一张图片、动作问题和 assistant 的语义答案 move，互不包含对方回答。已锁定的轴不再提问。

单次模型读出的请求数量

方法动作选择未锁定的两个轴
choice1 个请求1 个批次，2 个请求
yes_no1 个批次，3 个请求1 个批次，6 个请求

choice 读取候选字母分数；yes_no 逐候选计算 yes/(yes+no)，再归一化。两者沿用现有 boxed 单 token 读出，分数不是动作成功概率。批量处理不保证延迟减半。

共享规划如何复用？

  • no_plan：直接依据当前观察选择。
  • shared_full：复用完整推理与计划。
  • shared_plan_only：复用同一次生成中的计划部分。
  • shared_no_think：复用不带推理过程的短计划。

规划只看独立参考图，不看评测案例。full 与 plan-only 共享原始生成 token；不同读出方法也复用该计划。本文没有模拟或编造任何模型的规划文本。
