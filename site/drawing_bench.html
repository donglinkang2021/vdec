VDecision DrawingBench v2§

DrawingBench 是本仓库独立实现的看图绘图与空间关系评测。交互文章见 Drawing 指南。它借鉴官方 DrawingBench 的任务形式，但使用语义动作和画布坐标，不复现原作 GUI 操作协议；功能扩展本身不能证明模型评测效果更好。

默认版本为 v2。v1 的冻结题集、七动作协议、评分器与历史回放保留；通过 --dataset-version v1 显式选择。

题集和运行§

v2 有 16 个家族、48 个结构模板、512 个冻结案例。每家族两个已见模板：开发每模板 4 题，测试每模板 8 题；另一个模板仅用于 OOD，每模板 8 题。开发 128、常规测试 256、OOD 128。默认冒烟取开发集每家族一题，共 16 题；常规测试和 OOD 分开排名。

家族：方向关系、对齐、间距与距离、中间与分点、包含、重叠与接触、大小与比例、角度与平行、数量与排序、对称、网格与重复图案、连接关系、结构物体、图表与布局、颜色关系、修复与编辑。每题 2–10 个已有对象，最多 8 个最终评分目标。模板 ID、结构签名、颜色任务类型和复杂度均保存在冻结题集中。

# 默认 16 题开发冒烟，无 GPU
PYTHONPATH=src .venv/bin/python run.py --bench drawing --policy oracle
# 全量两轨规则策略
PYTHONPATH=src .venv/bin/python run.py --bench drawing --dataset-version v2 --split all --full-set --tracks geometry freehand --policy oracle
# 仅 OOD，筛选家族
PYTHONPATH=src .venv/bin/python run.py --bench drawing --split ood --families symmetry connectivity --full-set --policy oracle
# 全量两轨随机基线，三个 seed
PYTHONPATH=src .venv/bin/python scripts/validate_drawing_v2.py --policy random --output outputs/my-drawing-random-v2
# v1 开发冒烟仍为六题
PYTHONPATH=src .venv/bin/python run.py --bench drawing --dataset-version v1 --policy oracle
# 本地界面；真实模型需额外显式指定 --model
PYTHONPATH=src .venv/bin/python -m vdecision.benches.drawing.viewer
# 历史回放
PYTHONPATH=src .venv/bin/python -m vdecision.benches.drawing.viewer --run outputs/my-drawing-random-v2

Python：DrawingBench(dataset_version="v2", split="dev", limit="smoke", families=None)；limit=None 选择完整划分。tracks=("geometry","freehand") 分开出成绩。模型控制器为 readout（choice / yes_no）和 coordinate。规划条件为 no_plan、shared_full、shared_plan_only、shared_no_think；full 与 plan-only 复用同一次规划生成。缓存按版本、控制器、轨道、seed 和是否思考隔离。

动作与真实墨迹§

坐标为整数 0–80，每格 8 像素。geometry 工具为 line、rectangle、circle、ellipse、polygon、eraser；freehand 为 pen、eraser。矩形和椭圆使用对角点，圆使用圆心与半径控制点，多边形依次指定 3–8 个顶点并在 up 时闭合；真实画笔必须走完整条轮廓并回到起点附近。默认操作预算 geometry 192、freehand 768；v1 保持 64 / 256。

固定动作顺序为 tool, color, move, down, up, undo, finish, style, width, select, edit，choice 对应 A–K。所有操作始终可选；非法动作消耗预算，错误 JSON、越界值、布尔值和小数不会自动修正。

{"action":"color","color":"red"}
{"action":"color","rgb":[128,64,192]}
{"action":"style","style":"solid"}
{"action":"width","width":16}
{"action":"select","id":"A"}
{"action":"edit","operation":"move","x":40,"y":30}
{"action":"edit","operation":"rotate","angle":90}
{"action":"edit","operation":"scale","percent":150}
{"action":"edit","operation":"color","rgb":[128,64,192]}
{"action":"edit","operation":"style","style":"outline"}
{"action":"edit","operation":"delete"}

每行是独立动作。color 与 rgb 互斥，RGB 通道为整数 0–255；16 个预设为 black、red、green、blue、orange、purple、white、yellow、cyan、magenta、gray、brown、pink、navy、teal、lime。旋转为整数 −180～180 度，缩放为整数百分比 25～200。笔宽和橡皮直径 1～32 像素，初始分别为 3 与 16。工具、颜色、样式、宽度、选择和编辑要求先抬笔。

只有题目指定的初始对象及新增对象可编辑。选中状态仅公开 ID、权限和选中标记，不读取对象坐标、尺寸或 RGB。编辑移动以对象当前可见墨迹的包围盒中心为基准；旋转和缩放围绕同一中心。变换越界会原子拒绝。

橡皮沿实际路径擦除选中的可编辑对象；没有选择时擦除全部可编辑对象。锁定对象不受影响。每个对象保存墨迹与擦除掩码；变换同时作用于两者，不能恢复已擦掉的内容。undo 取消正在绘制或擦除的手势，否则恢复最近一次绘制、擦除或编辑前的场景。工具和颜色选择不占场景撤销历史。

模型请求与费用§

readout 定位为四轮九宫格：81→27→9→3→1。自定义 RGB 先选 17 个颜色选项之一，再按 R、G、B 顺序各做四轮四分：256→64→16→4→1。候选定位期间不移动、不擦除、不换色；完成全部参数后只执行一次动作。其它整数参数使用四分范围选择。

v2 动作 choice 请求 yes_no 请求 coordinate 请求 环境操作
move 5 11＋4×9＝47 1 1
预设颜色 2 11＋17＝28 1 1
自定义 RGB 14 11＋17＋12×4＝76 1 1

v1 的 yes_no move 是 43 次，不能与 v2 的 47 混淆。实际统计来自请求记录；操作数不等于模型请求数，批处理也不合并请求计数。coordinate 默认贪心，每次最多 128 token；保存原始生成与解析错误。

模型只看到题目、当前图片及操作状态，不读取参考解或评分真值，不收到中途评分。完整 RGB 明确指令精确匹配，看图配色允许每通道 ±8。

评分、记录和边界§

主指标是家族等权的完整成功率：自主提交、目标数量和属性正确、所有空间约束满足、无额外墨迹和未完成笔画。评分从每个对象擦除后的实际墨迹拟合形状，检查双向轮廓距离与内部填充，再进行带候选剪枝和关系剪枝的对象匹配；不使用隐藏参考落点。合法遮挡与真正擦除分别处理。

位置和轮廓容差 8 像素，指定分离间隔 16 像素，比例相对容差 10%，角度容差 5°。自由画笔要实际完成轮廓；空心、缺口、额外残留不能仅凭工具名通过。NumPy / SciPy 在 CPU 上完成数值检查。

输出包括 run.json、events.jsonl、summary.json、diagnostics.json、leaderboard.csv、最终 PNG，以及按内容哈希保存的 ink/*.png。事件状态引用墨迹检查点，不在每步重复存储位图。回放与汇总验证墨迹资产；缺失、损坏、基础设施失败或不完整结果不能排名。记录题集、协议、提示、渲染、模板和代码版本；v1/v2、常规测试/OOD 和两条轨道分别分组。

本轮无真实模型推理。规则策略知道参考解，随机策略不代表模型；模板预检仅证明请求可组装。交互文章中的候选分数标为“未测”。

维护§

冻结题集仅在显式维护时生成：PYTHONPATH=src .venv/bin/python scripts/build_drawing_cases.py --dataset-version v2。CPU 基线：scripts/validate_drawing_v2.py。模板与文章证据显式刷新：PYTHONPATH=src .venv/bin/python scripts/build_drawing_v2_snapshot.py。日常文章构建：python scripts/build_drawing_explainer.py，只读私有源码目录中的快照，不加载 tokenizer 或模型。网页为单文件，离线可读，压缩内嵌数据在浏览器本地展开。

保存的终局可用 scripts/regrade_drawing_v2.py --run 原始运行目录 --output 新目录 进行 CPU 重评。它保留实际动作与耗时，另存评分来源哈希与原始记录哈希，不重新执行策略或模型。
