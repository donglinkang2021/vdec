VAR：从预测下一个 token 到预测下一个尺度

正文与示例可直接阅读；加载后可查看保存的请求与逐步操作。

论文精读 · 实现追踪 · 四个可操作实验

一张图，必须从左上角开始逐格生成吗？VAR 把生成顺序改成尺度：先决定粗略结构，再一层层补充细节。同一尺度的所有位置，一起预测。

这里的“尺度”属于离散的潜在表示。模型并不是先画一张小 RGB 图片、再把它放大，而是不断预测新的残差 token，把它们累加到同一个潜在特征图上，最后交给解码器。

10256² 配置的串行尺度
680全部尺度的 token 总数
4096共享码本的词表大小

Tian、Jiang、Yuan、Peng、Wang · arXiv:2404.02905v2（2024-06-10）。代码固定于 78b9539。本文面向了解 Transformer 基础的读者；交互为教学计算，不运行生成模型。

01 · 改变的是生成顺序

Section titled “01 · 改变的是生成顺序”

传统图像 AR 把一个 16×16 的 token 网格排成长度 256 的序列，一次预测一个位置。VAR 使用 1、2、3、4、5、6、8、10、13、16 这十种边长，每一步预测整张 token map。大尺度依赖已经生成的小尺度，同尺度无需逐位置等待。

Raster AR：p(x) = ∏t p(xt | x<t, c)
VAR：p(r₁, …, rK | c) = ∏k p(rk | r<k, c)

c 是类别条件。十步不代表只有十个 token：Σ nk² = 680，比单尺度的 256 更多。减少的是必须串行执行的 Transformer 轮数，代价包括额外 token 和更大的同尺度注意力块。

实验一：沿两种顺序走一遍

结构示意 · 色块表示位置，不是模型生成内容

02 · 每一层编码“还没有解释的部分”

Section titled “02 · 每一层编码“还没有解释的部分””

第一阶段在 OpenImages 上训练多尺度 VQ autoencoder，空间下采样倍率为 16。编码器先产生特征 f，量化器维护残差 frest 和累计重建 f̂。每一步把残差降到当前尺度，寻找最近码本向量；将取出的向量放大到最终潜在分辨率，再经过 φ 修正，加入累计重建、从残差中减去。

rk = Q(downk(f − f̂k−1))
Δfk = φk(upfinal(Z[rk]))
f̂k = f̂k−1 + Δfk；最终图像 = D(f̂K)

同一个码本 Z 在全部尺度共享，但不同尺度的 token 描述的是不同阶段的残差。rk 是整数索引，不是颜色；Z[rk] 才是连续向量。真实模型的 32 维向量和卷积不能用“低分辨率图片”完全代替。

实验二：亲手拆开残差

人为构造的 4×4 标量特征 · 1→2→4 三个尺度 · φ 为恒等映射 · 块均值降采样、最近邻放大

这个简化只保留“残差量化再累加”的结构。真实代码使用 area 降采样、bicubic 放大与学习到的 φ，不保证每个尺度的像素误差都下降。

初始特征的均值是 1.5；间距为 1 时，首尺度量化为 2。

颜色只是辅助：每个格子都有数值。码本为 −4 到 +4 的等间距标量；距离相同时选较大的码值。

对照官方实现：插值、共享 φ 与第一阶段损失

f_to_idxBl_or_fhat 完成残差编码；get_next_autoregressive_input 完成生成时的累加。所有贡献先上采样到最终网格，不是只把上一尺度直接扩大一点。

论文写 K 个额外卷积，当前默认实现却用 share_quant_resi=4 在十个尺度间部分共享四个 φ。Phi 为 0.5 × Conv(x) + 0.5 × x；默认采用欧氏最近邻，代码另支持归一化相似度分支。

量化器的 forward 包含各尺度累计重建的 VQ 损失、commitment 项和 straight-through 梯度。论文第一阶段还包含图像重建、感知与对抗损失；不能把量化器内部损失当作完整 tokenizer 训练目标。

依据：论文算法 1、2 与 §4；官方 量化训练实现、默认构造器。

03 · 同尺度可以互相看，为什么没有泄漏答案？

Section titled “03 · 同尺度可以互相看，为什么没有泄漏答案？”

关键在于区分输入特征的位置与待预测的 token。第 k 个输入块已经具有 nk×nk 个位置，但它的内容是较粗尺度 r<k 的累计重建。当前尺度的真实 rk 只出现在监督目标里。

u₁ = 类别起始嵌入；uk = downk(f̂k−1)，k > 1
Mij = 0（scale(i) ≥ scale(j)）；否则 Mij = −∞

训练时把所有 uk 拼接起来，一次前向计算所有尺度的 logits。块下三角掩码允许当前输入块内部互相注意，但阻止访问更细尺度的输入——那些输入已经包含当前尺度真值的贡献。

    04 · 推理循环：缓存、条件与采样

    Section titled “04 · 推理循环：缓存、条件与采样”

    推理从类别嵌入开始，每轮只送入当前尺度。旧尺度的 key/value 缓存起来，同尺度可见；未来尺度尚未建立，因此不需要训练时的完整掩码。采样结果经码本查表、φ 修正和累加，再构造下一尺度输入。

    AdaLN 让类别条件生成归一化后的缩放、偏移及残差门控。训练以 0.1 概率把类别替换成空类别，为 classifier-free guidance 学到无条件分支。官方构造器的宽度为 64d、注意力头数为 d；默认 L2 归一化 q/k，并使用可学习的 attention scale。

    s = (k − 1)/(K − 1)，t = cfg × s
    guided_logits = (1 + t) × conditional_logits − t × unconditional_logits

    代码将有条件与无条件样本沿 batch 拼接，两支一起算。首尺度 t=0，后续线性增大。这里的 cfg 不能脱离公式直接当作所有实现通用的 guidance 系数。

    随后先 top-k、再 top-p 截断分布，再逐位置 multinomial 采样。当前 README 的 FID 建议为 cfg=1.5, top_k=900, top_p=0.96, more_smooth=False，生成 50,000 张 PNG（每类 50 张），转换为 NPZ 后使用外部评测工具。函数默认的 top-k/top-p 都是 0，因此“直接用默认参数”不等于 README 的评测设置。

    more_smooth=True 用 Gumbel-softmax 的软码本组合服务于可视化；代码明确排除它用于 FID/IS 基准。好看的演示图与可比的量化结果应分别看待。

    复现入口与实际交付范围

    README 给出 d16/d20/d24/d30/d36-s 的分布式训练命令。d16 为 batch 768、200 epochs；d30 为 batch 1024、350 epochs，并覆盖基础学习率和末端 weight decay。不能把论文的概括性超参数当成所有模型都共用一组配置。

    train.py 加载 tokenizer checkpoint；test_mode=True 冻结 VQVAE，优化器仅接收 VAR 参数。仓库包含 VQVAE 和量化损失实现，但未发现与论文复合损失对应的完整 tokenizer 训练入口。FID 部分依赖外部 toolkit，README 仍写采样脚本将稍后提供；现成 demo notebook 不等于完整批量评测与 rejection sampling 流程。

    代码存在 progressive training 分支，但默认 pg=0，量化器还标注未支持。本文不把这些分支当作已验证的论文配方。

    06 · Scaling laws：拟合了什么，没有证明什么

    Section titled “06 · Scaling laws：拟合了什么，没有证明什么”

    作者训练了 12 种大小的 VAR，约 18.5M 到 2.0B 参数、200–350 epochs，在 ImageNet 的 50,000 张验证图上测量交叉熵与 token 错误率；分别看最后尺度和全部尺度。图中的线性相关性发生在 log–log 坐标，不是直接把 FID 拟合成模型规模的函数。

    图 5 的 loss 拟合为 Llast = (2.0N)−0.23、Lavg = (2.5N)−0.20，横轴 N 以十亿参数为单位。论文还拟合不同模型训练轨迹的 Pareto 前沿，观察到更多计算与更低 loss / token error 的关系。

    读原图时必须保留的三处不一致
    • 正文写每 epoch 为 870B image tokens；按 1.28M × 680 得 870.4M ≈ 0.8704B，350 epochs ≈ 304.64B，与正文的累计约 305B 一致。因此“每轮 870B”疑似单位笔误。
    • 图 5 的 error 拟合图例做了舍入，与正文系数/指数并不完全一致；本文不据此生成伪精确预测点。
    • 图 6 左列标 all scale、右列标 last scale，但正文给对应系数的 last / avg 标记相反；图与正文的配对存在冲突。此外原文将累计计算轴标为 PFlops，并用 FLOPs/s 解释，量纲不清，本文不换算 GPU 小时。

    证据边界：有限区间内拟合好，不证明无限扩展不饱和；较低 token error 也不是逐像素准确率。350 对 1400 epochs 的比较不能直接等同总预训练成本降低四倍：tokenizer 还使用 OpenImages，模型大小和训练计算也不同。

    依据：论文 §5.2、图 5–6；本文仅展示原图，不从图像反推实验点。

    07 · 零样本编辑：保留一部分 token，重新生成另一部分

    Section titled “07 · 零样本编辑：保留一部分 token，重新生成另一部分”

    论文用 VAR-d30 演示补全、扩图和类别条件编辑：每个尺度保留指定区域的真实 token，剩余区域用采样结果。补全和扩图不输入类别信息，类别编辑则指定目标类别；不需要为这些任务单独微调。

    官方 notebook 把掩码缩放到当前 token 网格，阈值化后，用真实 embedding 覆盖保留区域；mask=1 表示保留，0 表示生成。在 ph×pw ≤ 3 的小尺度还强制全部保留，对默认序列就是第一个 1×1 尺度。这一细节意味着演示利用了输入图的粗尺度条件。

    示例单元格上方的 cfg、seed、more_smooth 变量与实际调用中的硬编码参数不完全一致，阅读时应以调用实参为准。样例体现可行性，没有提供足以推断任务成功率的量化基准；潜在网格上的保留也不保证解码后区域外每个 RGB 像素完全不变。

    依据：论文 §6、图 8；zero-shot notebook：get_edit_mask / replace_embedding / 实际采样单元格。

    08 · 值得带走的洞见与需要保留的判断

    Section titled “08 · 值得带走的洞见与需要保留的判断”

    有力的洞见：自回归的单位可以重新设计。把串行依赖安排在尺度之间、让尺度内部并行，配合适合这种顺序的 tokenizer，可以获得有竞争力的视觉生成系统。

    概率链式法则没有失效。论文把 VQ token 的双向相关称为违反 AR 数学前提，但任意联合分布都可以按给定顺序用链式法则分解。相关性本身不是反例。更合理的讨论是模型容量、归纳偏置、采样顺序及条件补全方式；这是本文的数学判断，不是论文原结论。

    “不 flatten”不宜按字面理解。实现仍通过 reshape / transpose 将二维网格组织成序列。改变的是生成因子分解和 attention mask，不是 Tensor 永远保持二维。同样，残差 token 的编码依赖原图特征与已有残差，不是仅凭较粗 token 就能确定编码真值。

    复杂度比较有前提。附录 B 的 AR O(n⁶) 对每一步重算整个前缀的注意力；使用 KV cache 后，AR 的注意力总工作量可降至 O(n⁴)，这里 n 是最终潜在网格边长，并固定层数和宽度。VAR 在几何尺度增长假设下也为 O(n⁴)，但有更短的串行依赖。计算量阶数、显存、硬件利用率与 wall-clock 都需要分别讨论，不能仅用 O(n⁶) 对 O(n⁴) 宣称所有实现都如此加速。

    范围仍然明确。本论文主要验证类别条件的 ImageNet 图像生成。文本生成图像和视频生成在文中属于未来方向；当前 README 链接的后续项目不能回填为这篇论文的证据。
