BrushBench v1：看图定位与画笔状态控制§

从 BrushBench 离线交互文章 开始：亲手操作一维二分和完整二维画笔，比较直线工具与真实笔迹。全部案例、规则轨迹和验证数据内嵌，单文件可断网打开。

本项目的第二个游戏环境，入口为 --bench brush。Snake 的动作主要是连续转向；Brush 默认引入分层决策：先判断该执行 pick、move 还是 drop，选择 move 后再根据同一张截图回答两个方向问题，控制器据此更新位置。另提供与本项目 DrawingBench 一致的 --controller coordinate，每步生成一个 JSON 动作，直接指定 move 的整数坐标。

方案与实施范围§

本轮实现四步：

  1. 固定动作语义、二分搜索区间和错误行为，建立可以独立运行的确定性环境。
  2. 接入现有模型适配器、单 token 候选读出和共享规划；双轴问题打成同一批请求。
  3. 冻结 108 个案例，保存可追溯提示、每步截图哈希、动作、区间、轨迹与结果。
  4. 用全题集规则策略、随机策略、真实笔迹对照、原生模板预检和自动化测试验证。

已完成以上实现。规则策略验证的是环境可解性；模板预检不加载权重。模型成绩必须在实际推理完成后报告。

相近 benchmark§

  • DrawingBench 官方仓库：通过鼠标绘图评估空间推理、GUI 操作和工具状态，包含规则评分与行动轨迹。
  • InkSlop 作者项目：包括迷宫描线、补全笔迹、笔迹向量化和识别重叠笔迹。
  • OSWorld 项目：真实桌面环境中的视觉交互任务，范围更广。

这些工作说明绘图作为评测载体已有先例。本环境的具体设计重点是小候选集的快速读出、二分定位、同图双轴分支，以及共享规划从 Snake 到另一种状态机的迁移。本次检索不构成“首创”证明。

二分定位不等于直线绘制§

直接落笔后按横纵轴二分移动，通常会产生折线、越过终点和折返，即使每次视觉判断都正确。因此提供两个明确分开的协议：

模式 move 的效果 用途
line_tool，默认 从落笔锚点到当前笔尖显示一条临时直线，旧预览被替换，pick 时提交 主评测：起终点定位与动作状态控制
freehand 每次移动都留下真实线段，历史笔迹不会清除 控制器诊断：展示二分移动和直线约束的冲突

默认模式相当于绘图软件的直线工具。它不测低层手部轨迹控制，也不会自动吸附到正确起终点。freehand 下二分规则策略也可能失败，不能把这种失败全部归因于模型。coordinate 协议允许一次直接移动到终点，因此可以在两种笔迹模式中都画出直线；它仍不评测受限小步的连续轨迹控制。

状态与动作§

当前状态 pick move drop
idle 提起画笔，进入 lifted 无效，消耗一步 无效，消耗一步
lifted 无效，消耗一步 根据视觉比较移动，不留墨 在当前位置落笔，进入 drawing
drawing 结束并提交本次尝试 更新直线预览或真实笔迹 无效，消耗一步

始终向模型提供三个动作，不屏蔽错误选项。提前落笔和提前提交均照常执行，最后由独立评分器判定。初始笔尖位置已在画布上可见，pick 是“抬笔”动作；这一版没有单独的工具栏抓取步骤。

二分模式中，模型看到的文本状态只有 phase、当前目标名称 S/E、之前回答产生的轴锁定状态和剩余步数。coordinate 模式省略不适用的轴锁定字段。两种协议都不向模型提供目标与笔尖坐标、真实是否对齐、正确答案、搜索区间和评分。S 为绿色起点，E 为粉色终点；笔尖由空心准星表示，避免遮住目标中心。

默认 33 × 33 个离散位置。每轴保留闭区间 [lo, hi]，初始 [0, 32]。在当前位置 p：

  • left / above：hi = min(hi, p - 1)，新位置 floor((lo + hi) / 2)。
  • right / below：lo = max(lo, p + 1)，新位置 floor((lo + hi) / 2)。
  • same：立即锁定该轴，后续不再询问；不读取真值验证。

持续维护上下界，而不是每次都回到画布边界取中点；排除已否定的位置避免整数舍入卡死。drop 后两个区间和锁定状态重置，目标切换为 E。错误方向导致空区间时，本局以 search_exhausted 失败结束。默认最多 40 个高层动作。

模型输入与双轴批量读出§

动作请求的顺序是：任务说明 → 当前状态 → 图片 → pick/move/drop 选项 → 原生 assistant 的 boxed 单 token 读出。

选择 move 后，两个分支分别包含同一段状态、同一张图片、动作问题、assistant 的语义答案 move，然后追加各自的横向／纵向问题及选项。move 是从上一步候选分数选出的语义动作，不是额外采样生成的文本。两个分支互不包含对方答案。

parallel 将未锁定的轴送入一次 backend batch，等全部结果返回再更新位置。没有两个线程同时修改环境或调用共享模型。alternating 每次只问一个轴，锁定后只询问剩余轴。

读出方法 动作选择 两轴 move 追问
choice 1 个请求，读取 A/B/C 的 logprob 1 个 batch，2 个请求
yes_no 1 个 batch，3 个逐候选请求 1 个 batch，6 个逐候选请求

复用现有 \boxed{ 边界、softmax 和 yes/(yes+no) 归一化。分数不是成功概率。两轴打包不代表延迟必然减半，需要真实后端实测。

支持 no_plan、shared_full、shared_plan_only、shared_no_think。每个 seed 在独立参考图上生成规划，full 和 plan-only 复用同一次生成的原始 token；不同读出方法也复用该计划。不支持思考的模型会将相关条件记为 unsupported。当前版本尚未接入 Snake 的 manual_plan、neutral_prefix、per_step_cot 扩展条件。

Coordinate：直接生成坐标动作§

--controller coordinate 参考本项目 DrawingBench 的 coordinate 实现，使用同一模型适配器与生成后端。每个高层动作只发起一次生成，贪心解码（temperature=0），最多 128 token。合法输出为以下三种 JSON 对象之一：

{"action":"pick"}

{"action":"move","x":10,"y":20}

{"action":"drop"}

坐标是画布格点，不是图片像素：冻结题集范围为 0–32，左上格点为 (0,0)，x 向右、y 向下。模型仍须从图像估计位置。一次 move 同时更新 x/y，不经过二分、轴锁定或中间落点。pick/drop 的状态转换、提前提交、步数限制与评分函数沿用原规则；line_tool 替换预览，freehand 为每次 move 留下一条线段。

校验不接受额外或重复字段、缺失字段、小数、布尔坐标、越界坐标、代码围栏、解释文本或多个对象。达到生成 token 上限的输出也无效，即使其前缀看起来合法。无效输出消耗一步，笔尖和笔迹不改变，不截取 JSON、不取整、不裁剪、不吸附。原始输出、生成 token、finish/stop reason、解析错误、提示 token 和截图哈希保存在每步的 coordinate_batch；解析成功的命令保存在 coordinate_action。

coordinate 支持现有四种规划条件；shared_full 与 shared_plan_only 复用同一次生成的计划，使用独立的坐标任务规划说明。--methods choice yes_no 不会复制 coordinate 实验，矩阵中的 method 固定为 coordinate。--axis-schedule alternating 不适用于此模式，配置会明确拒绝；manifest 的 axis_schedule 和 axis_lock_source 为 null，movement_protocol 为 absolute_integer。轴回答准确率为 null，生成请求与 token 成本正常计入 diagnostics。

--policy oracle --controller coordinate 直接读取真值验证环境可解性；random 模式随机选择动作，在 move 时均匀采样合法格点。二者都不加载模型。coordinate 与二分的动作空间和成本不同，分数应按 controller、ink_mode 和 policy 分开比较。原交互文章中的 11.11% 真实笔迹结果对应二分规则策略，不是 coordinate 成绩。

# 坐标模式配置与矩阵预览，不加载权重
PYTHONPATH=src .venv/bin/python run.py --bench brush --controller coordinate --dry-run

# 全部 108 题：直接坐标 + 真实笔迹的规则验证
PYTHONPATH=src .venv/bin/python run.py --bench brush --controller coordinate \
  --policy oracle --split all --ink-mode freehand

# 模型冒烟；四种规划条件，结果按 coordinate 单独记录
PYTHONPATH=src .venv/bin/python run.py --bench brush --controller coordinate \
  --model models/Qwen/Qwen3.5-4B --limit 6 \
  --conditions no_plan shared_full shared_plan_only shared_no_think

Python 接口：BrushBench(controller="coordinate", ink_mode="freehand")。--preflight 同时检查二分与 coordinate 的原生模板，不加载权重。这里的规则验证与模板检查均不代表模型推理成绩。

题集与指标§

冻结文件为 src/vdecision/benches/brush/cases_v1.json，构造工具为 scripts/build_brush_cases.py。正式运行仅读取冻结数据。六类案例为 horizontal、vertical、diagonal、shallow、steep、boundary；每类开发 6 个、测试 12 个，共 36/72。起终点几何去重时忽略方向，开发／测试不会出现反向复用的同一线段；规划参考图另置。部分案例初始已对齐一个轴或已位于起点，检查是否会产生多余动作。

主指标是六类等权完整成功率。每局成功要求：已提交、落笔点恰为 S、结束点恰为 E、全部可见笔迹到目标线段的最大距离不超过 0.25 个格距。端点要求精确对齐；0.25 容差只用于笔迹偏离。评分直接读取几何，不使用模型裁判。真实笔迹的路径长度比作为额外诊断报告，不与主指标混成一个分数。

同时记录：起终点误差、路径长度及比值、最大偏离、动作数、无效动作、结束原因、轴回答准确率与关系分层、动作对规则策略的符合率、请求数、batch 数、输入输出 token 和耗时。动态轨迹上的轴准确率受各模型访问状态影响，不能视为独立固定题集上的视觉能力排名。action oracle agreement 是最短策略符合率，不把所有额外确认动作判成不合法动作。

逐步读出成本位于 diagnostics；规划 token、耗时和生成请求数单列在 summary 的 planning 中，每份复用计划只记录一次。导出的 leaderboard 同时带有 split 和 subset 标记。

--controller scripted 是固定流程消融：只依据模型报告的锁定状态切换动作，不利用真实坐标；--policy oracle 才允许读取真实几何，用于验证环境；--policy random 是随机参照。三者与模型自主控制的结果应分开解读。直线工具、真实笔迹、双轴批量和交替协议也应分开比较。

运行§

# 查看配置和实验矩阵，不加载模型
PYTHONPATH=src .venv/bin/python run.py --bench brush --dry-run

# 所有冻结题的规则策略验证，不需要 GPU
PYTHONPATH=src .venv/bin/python run.py --bench brush --policy oracle --split all

# 原生模板预检，不加载模型权重
PYTHONPATH=src .venv/bin/python run.py --bench brush --preflight \
  --model models/Qwen/Qwen3.5-4B

# 开发集模型冒烟；limit 按几何类别交错选择，不能当作完整榜单
PYTHONPATH=src .venv/bin/python run.py --bench brush --split dev --limit 6 \
  --model models/Qwen/Qwen3.5-4B --save-gifs

# 同题比较现有四个核心条件
PYTHONPATH=src .venv/bin/python run.py --bench brush --split dev \
  --methods choice yes_no \
  --conditions no_plan shared_full shared_plan_only shared_no_think

# 固定流程、交替轴的对照
PYTHONPATH=src .venv/bin/python run.py --bench brush --policy oracle \
  --split all --controller scripted --axis-schedule alternating

# 真实笔迹对照与规则策略动画
PYTHONPATH=src .venv/bin/python run.py --bench brush --policy oracle --split all --ink-mode freehand
PYTHONPATH=src .venv/bin/python scripts/preview_brush.py --output outputs/my-brush-demo

# 离线汇总、自动化验证
PYTHONPATH=src .venv/bin/python run.py --summarize outputs/某次运行 --details
PYTHONPATH=src:tests:. .venv/bin/python -m unittest tests/test_brush.py -v

输出目录必须不存在。run.json 记录代码哈希、数据哈希、实际案例、规则、模型和协议；events.jsonl 记录完整提示 token、分支分数、输入画面哈希及前后状态，可用对应版本渲染器重建每张画面。summary.json、leaderboard.csv 和 diagnostics.json 支持离线汇总；--save-gifs 为每局保存动画。未完成、重复、损坏或推理异常的配置不排名。游戏失败是有效样本的零分，加载或推理失败不记成模型任务失败。--limit 生成的分数仅用于所选子集，应查看 manifest 后再比较。

Python 接口为 from vdecision import BrushBench，用法与 SnakeBench 相同。运行实际模型仍使用现有 vLLM／Transformers 后端和 GPU 作业流程；本实现不自动提交 GPU 作业。

后续更有代表性的游戏§

优先把新维度与已有能力分开，每个游戏设置一个清晰主指标：

  1. 分类搬运：pick 一个物体、二分移动、drop 到符合颜色／形状条件的容器；新增属性绑定、目标选择和多对象记忆。
  2. 开关接线：只允许连接满足颜色或逻辑约束的端口；新增视觉关系、多步约束和状态依赖。
  3. 沿轨描线：笔尖只能小步移动，需沿指定曲线并避开障碍；新增连续路径控制。必须另设移动协议，不能沿用当前二分法后声称测到轨迹控制。

先用 Brush 的完整开发集检查方向判断、状态切换和共享规划收益，再冻结下一款游戏的规则与测试集，避免把一个环境中的问题带到更多 benchmark。
