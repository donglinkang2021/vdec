三模型规划与视觉推理实验

下文记录 v8 实验的配置与运行方法，使用 main-v1 冻结数据。v9 的变化单列在末尾；两版结果不可混合比较。当前分数和案例见 实验说明页。

生成和读出

Section titled “生成和读出”

先生成推理或计划，再读取候选分数。两阶段的采样设置独立。recommended 保留历史参数；probe 使用 T=1、top_p=1、top_k=-1 生成 thinking，再 greedy 生成 plan；greedy 两阶段均为 greedy。

model_default 从 checkpoint 的 generation_config.json 读取采样参数。缺失字段用当前 Transformers 默认值补齐；缺文件则报错。run.json 保存原值、解析值与文件哈希。可用 --generation-config FILE 显式覆盖。boxed 读出使用中性参数，不继承生成采样。

Qwen3.5-4B 缺少默认采样文件。经确认，使用模型卡参数文件 experiments/qwen35_model_card_sampling.json。矩阵通过 experiments/snake_generation_configs.json 加载；单独运行时需传 --generation-config experiments/qwen35_model_card_sampling.json。这是显式覆盖，不是 checkpoint 默认文件。

条件生成执行上下文
no_plan无当前截图与问题
shared_fullthinking + plan同一份完整 thinking + plan
shared_plan_only与 full 共享生成结果仅保留 plan
shared_no_think关闭 thinking 生成 plan直接 plan
manual_plan无固定任务清单
neutral_prefix无与人工清单 token 长度接近的中性段落
per_step_cot当前问题独立 thinking原始 thinking token、结束标记、boxed 直接读出

人工计划由 prefixes.py 提供，也可用 --manual-plan-file 替换；正文不按生成预算裁剪。当前问题 CoT 的预算为 --step-thinking-tokens 128/256/512，不生成 plan。choice 每种排列单独思考，yes/no 每个候选单独思考。自然结束立即读出；预算耗尽补原生结束标记。v8 的异常提前结束记失败。

--repeat-id 表示覆盖完整数据集的一次独立重复。--seeds 将同源题组（family）分配给共享计划，不代表多次完整重复。分片不改变问题的随机种子。模型使用自己的原生模板；Gemma 使用通道标记。每份计划保存正文、token 长度和来源哈希。

运行顺序

Section titled “运行顺序”

本轮不运行 test。564 个 v9 dev 配置已完成并核对，下一步运行 Episode 闭环。一个配置可包含多种条件和读出。

已验证的执行路径默认直接提交实验。增加 seed、重复编号或已支持范围内的预算，不要求重跑 GPU 冒烟。GPU 验证不是每批提交的前置步骤；具体触发条件见下文“验证”。

查看分阶段命令、冻结与闭环选型

在项目根目录使用同一虚拟环境、源码快照、vLLM 配置、精度及缓存设置。experiments/snake_models.json 给出三个模型路径，可复制后改为分配节点可访问的路径。

随后按 shared、prefix、cot 分阶段执行。shared 包含 plan 128/512/1024、四种生成方式、三个重复；cot 包含 128/256/512、三个重复。所有阶段包含四个静态榜和两种读出。每个 split 共 564 个独立运行目录：baseline 12、shared 432、prefix 12、cot 108；其中每个 shared full/plan-only 配对在同一个运行内生成一次。主流程不会重复运行 no_plan。

显式覆盖映射文件格式为 {"qwen35-4b":"experiments/qwen35_model_card_sampling.json"}，通过矩阵命令的 --generation-configs FILE 使用。运行失败立即停止，保留已有输出；工具不会覆盖或自动重试部分运行。

闭环使用相同 30 个 seed、128 步上限，包含无计划、人工计划、每模型每读出的最佳生成计划和最佳 per-step CoT。共享计划按 dev Decision 安全率、执行时间顺序选择；CoT 同分选短预算。Episode 使用自己的任务规划提示重新生成计划。随机基线只随 no_plan 运行。

分数和蒸馏接口

Section titled “分数和蒸馏接口”

每次运行保存主分数、错误诊断和延迟。比较时，用相同题组比较两种方法。先汇总独立生成重复，再以 family 为单位抽样 2000 次；每次保留组内全部问题和排列，并保持 Safety / Decision 的分层权重。重复分数和标准差单独报告。未完成配置只展示失败与缺失情况，不排名。

动作一致不代表动作正确。还需检查 Decision 安全率、闭环食物数、碰撞和延迟。中性前缀只控制近似长度，仍可能影响语义。

teacher 导出需要两个不同 repeat 的 CoT 运行，且模型、预算、配置一致。逐项核对图片、问题和候选顺序。导出图片与哈希、两次候选分布、均值、无思考分布 p0，以及推理 token 和终止状态。yes/no 额外保留原始二元概率。

导出标记 purpose=evaluation_only。正式训练集必须另建，并与 benchmark 的 dev/test family 隔离。本轮不启动 vdistill 训练。SII-Decision 的候选分布蒸馏可作为后续损失参考，但官方语言 backbone 路径需要多模态适配：论文 v2 §6、官方 learning.py。

验证

Section titled “验证”

保留 CPU 回归测试，按改动范围运行。离线模板检查验证输入边界。已通过 GPU 验证的模型和执行路径，后续默认直接提交实验，不重复跑冒烟。

只有更换 checkpoint、tokenizer、原生模板、推理后端或关键运行环境，修改生成／读出路径，或出现尚未定位的 GPU 错误时，才按风险做必要的 GPU 检查。检查限于受影响的模型和路径，不默认重跑三模型整套冒烟。文档、汇总或报告改动不触发 GPU 检查。

查看 CPU 回归与可选 GPU 检查命令

离线模板检查不等于 GPU 推理检查；测试替身通过不代表已获得三模型分数。GPU 冒烟脚本的 smoke.json 区分 not_performed、failed、passed，完整 benchmark 以 run 原始事件及汇总为准。

v9：计划提取与失败重试

Section titled “v9：计划提取与失败重试”

v9 保留原始输出，并从最后一个原生思考结束标记之后提取 plan。标记异常、空 plan 和预算截断均记录下来。原始 token 不改写；full 使用完整轨迹，plan-only 使用提取后的 plan。

每次请求最多重试两次，保持输入 token 和采样 seed 相同。一个配置失败后仍继续其他配置。未完成配置只显示已观察分数和覆盖率，不提供完整主分数。

v9 重新运行 12 个 baseline 和 552 个 dev 配置。v8 原始结果继续保留，不与 v9 合并。

历史问题与回归范围

Section titled “历史问题与回归范围”

此前四份真实输出因旧版格式校验被拒绝，涉及 Qwen3.5、Qwen3-VL 和 Gemma。生成正文可能含孤立或重复的思考结束标记，也可能在预算处截断。格式异常不能作为跳过读出的理由；正文很短也不能作为拒绝依据。

核心规则如下：

  • 在原始 token 中取最后一个 </think> 或 <channel|> 之后的内容。没有标记则保留全部输出，不要求开始标记匹配。
  • 自然结束立即使用。预算截断保留已有内容。提取为空仍执行读出并记录 empty_plan，不补生成、不换 seed、不回退为 no-plan。
  • full 保留原始轨迹；plan-only 从同一轨迹切片。成本按实际生成的原始 token 统计。
  • 保留候选 token 边界、图像对应关系和上下文长度检查。运行异常与生成格式分开处理。

历史大段 token 不再作为仓库测试数据保存。tests/test_permissive_plans.py 使用短合成样例覆盖无标记、重复／混合标记、多 token 标记、Gemma 通道标记及空正文，并可用三个模型的本地 tokenizer 重测。现有 CPU 测试继续覆盖自然 EOS、预算截断、共享轨迹、固定 seed 重试和部分结果报告。真实 GPU 重放工具仅作可选排障用途。

查看 v9 字段、终止规则与版本记录

snake-bench-v9 uses last_close_v1: find the last token sequence encoding </think> or <channel|> and take the suffix as the plan. If neither occurs, use the entire generated plan. Repeated/orphan markers, empty suffixes and budget truncation are observations, not generation errors. Raw generated IDs remain in raw_plan_ids; plan_ids contains the extracted suffix. Full CoT execution keeps the raw trajectory, while plan-only/direct execution uses the extracted plan. A native EOS during thinking finishes the response without another plan request.

Runtime requests retry at most twice with identical prompt tokens and sampling seed. A failed readout does not regenerate its plan or current-question reasoning. Each retry is recorded, and a failed configuration does not stop its siblings. Partial results expose observed_score, coverage, bundle_coverage, failure_rate, and score_status; the primary score remains unavailable until its full required coverage is present. Request failures never receive fabricated candidate distributions. plans.html shows raw/extracted plans and termination metadata for each run. Old v7/v8 result artifacts remain readable and unchanged.

The v9 restart uses a fresh source snapshot and repeats all 12 baselines and 552 dev configurations. Historical v8 scores cannot be pooled into v9 comparisons.

2026-10-19：v9 dev 完成，转入闭环

Section titled “2026-10-19：v9 dev 完成，转入闭环”

已核对 36 个平台任务、564 个配置的退出码、原始事件、候选分数、配置及源码哈希。全部配置完整，541,728 条候选读出有效，覆盖率 100%，失败率 0%。重新从原始事件计算的汇总与各运行的 summary.json 一致。三次生成重复合并后，共 576 个“方法 × 任务 × 模型 × 读出”分数。

  • Perception：六组最高分都来自 512-token 当前局面 CoT。yes/no 下，Qwen3.5 为 57.22% → 61.74%，Qwen3-VL 为 43.16% → 48.62%，Gemma 为 53.65% → 59.58%。格子内容与尾巴识别仍弱；512-token CoT 下六组尾巴格识别率为 0%–9.72%。
  • Safety：Gemma yes/no 的 probe、1024-token shared_full 为 41.20%，比基线高 16.20 个百分点，配对 95% 区间为 [6.19, 25.98]。
  • Decision：六个最佳生成计划的配对区间均包含 0。Qwen3.5 yes/no 的 256-token CoT 为 52.31%，相对无计划高 4.17 个百分点，区间 [0.12, 8.96]。
  • 计划：3,456 份中有 1,954 份截断，无空计划。全部保留并执行；原始生成共 4,152,761 token。

以上配置在同一 dev 上选出。区间未校正多重比较，不能视为独立验证。Readout 一致率不单独支持能力提升。

Episode 已固定 42 个配置：每模型的无计划及人工计划各跑两种读出；最佳生成计划和 CoT 按读出分别选择，各跑三个重复。所有重复都覆盖游戏 seed 0–29，每局最多 128 步。共 1,440 局模型评测，另含 90 局随机对照。生成计划使用 Episode 专用提示重新生成。本轮不启动 test 或蒸馏训练。

2026-10-19：Episode 完成

Section titled “2026-10-19：Episode 完成”

42 个正式任务均为 job_succeeded，进程退出码均为 0。原始事件重算与保存汇总一致。1,440 局模型评测、59,695 次候选读出完整，覆盖率 100%，运行失败率 0%。另有 90 条随机对照记录；三个模型下轨迹相同，去重后按 30 个 seed 计。全部 61,285 步通过独立重放，截图哈希、执行动作、食物数及终止原因一致。

  • 生存不等于进食。 Qwen3.5 choice 无计划全部走满 128 步，食物为 0，重复状态占 95.9%。人工计划为 0.233 份 / 局，配对差值区间 [0.100, 0.400]，但 73.3% 的局仍零食物到达步限。
  • CoT 有局部收益，避障仍不可靠。 Qwen3-VL yes/no 从 0 升到 0.300 份 / 局，配对差值区间 [0.156, 0.478]；动作耗时中位数为 3.332 秒，约为对应基线的 80 倍。六组逐步 CoT 共 540 局，全部以碰撞结束。
  • 共享计划的长生存可能只是循环。 Gemma choice 从无计划的 5.3 步升到共享计划的 52.1 步，但平均食物数都为 0.033。共享计划中 36.7% 的局零食物走到步限。
  • 当前优势不够支持直接蒸馏所有行为。 没有方法平均吃到 1 份食物。应分开评价进食、立即避障与循环；不能把更多思考当作正确示范的保证。

置信区间以游戏 seed 配对抽样 10,000 次；同 seed 的生成重复先取均值。各重复分数另报，不把三次重复当作 90 个独立 seed。区间未作多重比较校正。Episode 未重扫所有预算，因此不估计预算的因果效应。本轮没有运行 test。

延迟使用日志的 action_seconds：从模型执行前到环境更新后，包含提示构造、思考、读出及环境检查，不含截图渲染和前后日志写入。后两项缺少逐步计时，不能补出完整环路的每步墙钟值。HTML 同时列出整局墙钟时间、首步、后续步、p50/p95 和计划预生成成本。模型加载单列。整局耗时除以步数只作摊销均值。

报告新增三个同 seed 案例，按明确条件选取中位项，避免只展示最好一局：Qwen3.5 choice seed 12；Qwen3-VL yes/no seed 25、CoT repeat 0；Gemma choice seed 11、共享计划 repeat 2。图片由冻结渲染器重建并核对哈希。所有 1,440 局均可查询逐步延迟并下载 CSV。

产物：.cache/episode-review-20261019/results.json、scores.json、steps.csv、audit.log；原始输出保留在 outputs/episode-v9-20261019/。HTML 内嵌汇总、全部逐步耗时及案例截图，可离线阅读。
